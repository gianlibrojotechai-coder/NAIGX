# M-08 partial rubric review — corpus-v1

Generated by `npm run review:packets`. Do not edit the packets by hand before
reviewing; regenerate instead.

**What this is.** One packet per committed recording, carrying the submitted
input, the stage outputs that were captured, and the `docs/10` §4.4 record to
fill in.

**What it is not.** Not an M-08 pass, and not capable of becoming one. `docs/10`
§3.5 requires all seven criteria to pass per analysis; C-3 and C-6 have no
material in these recordings and are marked not assessable. §4.1 requires ≥20
analyses per input type, which this set does not reach.

**Corpus, not runtime.** The recordings were captured 2026-08-14. Per
`docs/12` D-24 they are not evidence that the prompts now in force produce
these responses.

**Reviewer independence.** `docs/10` §4.3 excludes AI review in any capacity,
for any criterion. Every verdict in these packets must be written by a human. If
the reviewer is also the author of the analysis, the result is recorded as
single-reviewer and cannot satisfy an agreement measurement. A reviewer who did
not build this system is what §8 ambiguity A-1 has been waiting for — and if two
people review the same packets, §5 agreement measurement becomes available.

**How to review.** Read `INDEX.md` for what exists and which criteria each
packet can support. Then, per packet: read the input, read the stage outputs,
and record a verdict **and** evidence for C-1, C-2, C-4, C-5 and C-7. §3.3 is
strict — a verdict without evidence is not recorded as a verdict. C-3 and C-6
arrive marked not assessable; leave them. Judge only what is in front of you.

**Do not open `UNBLINDING-INDEX.do-not-open-before-review.json` until the verdicts are written.** It carries
the fragment version and model identity that §4.2 keeps out of the packets.
