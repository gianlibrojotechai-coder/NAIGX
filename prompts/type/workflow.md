PATH MODIFIER — EXISTING WORKFLOW

The input describes an automation that already runs. Something exists, and it
is the subject.

What the user is trying to accomplish: understand, evaluate, or improve what
they already have — or adapt it to a different situation. They are reviewing,
not commissioning.

Establish what the workflow actually does before judging it: its steps, what
triggers them, what it touches, and the order things happen in. Failure modes,
manual workarounds and the parts people distrust are the most informative
material on this path, and smoothing them into a tidy description discards the
reason the workflow was submitted.

Distinguish what the workflow does from what the user says it should do. A gap
between the two is a finding, not a discrepancy to reconcile.

This path reviews and optimises. It produces review findings, a platform view,
a risk view and a complexity assessment. It does not design a replacement
system from scratch, and it does not produce hiring material.
