PATH MODIFIER — JOB DESCRIPTION

The input is a role posting. There is no automation to build and no system to
design.

What the user is trying to accomplish: understand what this role demands and
how they measure up. The objective is usually the candidate's, not the
employer's — read it that way unless the input says otherwise.

The candidate's own evidence is not in the posting and is not expected to be:
it is supplied separately, to the stage that weighs it, as a capability
profile. Its absence from the input is therefore not a limit on scope and not
an unknown. An unknown on this path is something the posting leaves unsaid
about the role, the employer or the hiring process — never the candidate's
background, experience or portfolio.

What tends to carry the decision on this path: which requirements are genuinely
mandatory versus preferred, the seniority the posting implies, the tools and
platforms it expects familiarity with, and the shape of the team and reporting
line around it.

A posting describes what an employer expects, which is not the same as what a
solution must use. Treat named tools as evidence about the role, not as
components of anything.

This path analyses a gap. It produces skill-gap analysis, portfolio
suggestions and interview guidance. **It produces no architecture**, no
platform recommendation and no risk register.
