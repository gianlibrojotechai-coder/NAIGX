## 2. The request contract — checked against the adapter, nothing to fix

The migration guide lists what a request to `claude-opus-5-5` rejects with
400. Each was checked against `src/provider/adapters/anthropic.ts`:

| Rejected on Opus 5.5 | Does NAIGX send it? | Where |
|---|---|---|
| `thinking: {type: "disabled"}` or `budget_tokens` | **No** — the adapter never sends a `thinking` field | `invoke()` builds `model`, `max_tokens`, optional `temperature`, `output_config` only |
| `temperature`, `top_p`, `top_k` off their defaults | **No** — `THINKING_GENERATION` (`/^claude-(sonnet-5\|opus-5\|fable-\|mythos-)/`) matches `claude-opus-5-5`, so `temperature: 0` is withheld and `low_variance_unavailable` is noted | `acceptsSamplingParameters` |
| `tool_choice` `any` / `tool` | **No** — structured output is `output_config.format`, no tools | `outputConfig` |
| Assistant prefill | **No** | — |
| Reading `content[0]` as text | **No** — blocks are selected by `type`; `thinking` blocks first are expected | `textOf()` |

So the switch is configuration, exactly as D-69 was. The prefix match also
means the thinking token budget (`DEFAULT_MAX_TOKENS_THINKING` = 16 000)
applies. Two consequences worth stating:

- **Effort must stay explicit.** Opus 5.5's default is `medium`; the host
  sets `PROVIDER_EFFORT=high` (D-69) and the adapter always sends it. Leaving
  the variable unset would silently drop to `medium`. `medium` is a further
  cost lever the owner may choose later; it is not chosen here.
- **`acceptsSamplingParameters` is now asserted for the 5.5 ids** so a future
  regex edit cannot regress them (`tests/unit/anthropic-sonnet5.test.ts`).

## 6. Observed during the switch — a Stage 7 failure on Opus 5, not on 5.5

The owner ran the same job description twice on Opus 5 before the switch.
The 02:44 UTC run completed (6 calls, $0.8600, 316 s). The 02:57 run
**failed at Stage 7** after four successful provider calls ($0.6172 spent,
nothing presented): the parser refused the recommendation because
`requirement "req-19" is reported as both matched and a gap`. `retry_count`
0, by design — [D-91 §3](66-D-91-Sample-Variance-Policy.md) records the
owner's choice of **no Stage 7 regeneration** ("a refusal is a finding about
the prompt, not a retry"), and `SA §11.3` says stages 5–10 never auto-retry.

Same input, same model, same fragments, one pass and one refusal: this is
sample variance of the kind D-91 names, on a rule the parser enforces. It is
recorded here because it cost the owner an analysis and is the second live
Stage 7 refusal on record (the first, D-90 §7, was fixed in the fragment). The
choices, none taken by this record:

1. Resubmit — variance, so a second attempt usually passes; costs a full run.
2. Reverse D-91 §3 for the two *partition* rules only (a requirement in both
   lists, or in neither): one **informed** regeneration with the parser's
   reason appended, as Stage 6 and Stage 2 already have. Owner decision.
3. Strengthen the fragment's partition wording — a fragment change, so a
   capture and a pass reference through the unchanged gate.
